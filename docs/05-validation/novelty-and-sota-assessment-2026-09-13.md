# 创新性、强基线与研究差距评估

核对日期：2026-09-13 CST。结论：**有工程集成价值，算法创新尚未确立；未获得同配置SOTA证据，正式验收仍为NOT_ACCEPTED。** 本文是基于源码、实际工件与一手文献的技术判断，不是独立审稿结论。论文数字均属于作者实验；ASR越低越好，任务效用越高越好。

后续实测更新：Lab3090 的 Qwen3.5-9B 已完成 [v4 完整系统开发对照](agentdojo-lab3090-contract-v4-review.md)及 [PromptArmor 思路的输入清洗参考对照](context-filter-reference.md)。后者修复版正常8/8、攻击0/16、无未知，正在扩大正常任务范围；它不包含产品动作门控，也不是作者代码复现。下文27B/早期候选数字保留为历史证据，不作为最新9B成绩或跨方法同配差值。

## 当前设计的新意在哪里

| 当前设计或候选 | 已有工作与重叠 | 当前可合理主张的贡献 |
|---|---|---|
| Hook/MCP入口、工具前策略DSL、确定性执行约束 | [Progent v1，2025-04](https://arxiv.org/html/2504.11703v1)已提供工具调用权限DSL、拒绝后处理及任务生成策略 | 面向现成编程Agent的工程适配与运维闭环；接口组合本身不是新算法 |
| 仅从原任务规划、核对工具与参数 | [IPIGuard](https://arxiv.org/html/2508.15310v1)的工具依赖图、[Task Shield](https://aclanthology.org/2025.acl-long.1435/)的任务对齐、[PlanGuard](https://arxiv.org/html/2604.10134v1)的隔离规划/参数核验已有直接先例 | task-plan-v1的逐参数来源证明、有限算术和一次性配额是待验证的具体实现差异；不能将“先规划再验证”命名为首次提出 |
| 来源标签、任务权限、策略和数据流约束 | [CaMeL](https://arxiv.org/abs/2503.18813)已隔离控制与数据；[AgentFlow v1，2026-08-24](https://arxiv.org/html/2608.22868v1)包含污点、路径策略、任务能力与受控释放 | 需要明确比已有语义多解决哪类合法动态参数及哪些攻击；我们尚无对应形式化证明 |
| 子Agent权限收缩、会话历史与授权绑定 | [Bounded Agents v1，2026-08-16](https://arxiv.org/html/2608.15888v1)研究委派权限、预算收缩和动作组合约束 | 现有权限交集是必要安全功能，不能单独当作新研究命题 |
| 审批后精确执行、防替换/重放、执行结果追踪 | [SecureClaw](https://arxiv.org/html/2606.09549v1)已有PREVIEW/COMMIT与精确请求执行边界 | 真实客户端上可复现的覆盖率、恢复与低开销证据仍有系统论文价值；当前Codex/Claude真实E2E未签收 |

本工程没有同名[AgentSentry论文](https://arxiv.org/html/2602.22724v1)的时序反事实诊断算法，对外必须区分归属。内部代码重复率只衡量第一方代码的重复片段；独立编写已有算法也不能据此证明算法原创。

最值得验证的具体问题是：**多步任务需要使用外部查询得到的收件人、金额或文件路径时，怎样允许合法参数进入动作，同时阻止外部内容扩大授权？** 例如“按发票付款”不能只匹配用户原文中的账号，但“参数确实来自发票”也不能证明发票事实真实或付款获授权。候选的来源证明只能证明数据出处与绑定一致性，规划器的语义判断仍是信任假设。

研究主线可收敛到一个可被否证的假设：在相同主模型、攻击与工具预算下，参数来源约束能比粗粒度权限和纯语义核验保留更多正常任务，且不增加成功攻击。跨会话记忆的权限保持和按风险选择昂贵核验是后续扩展；这些目前都是待证明方向，不标记为已完成创新。

## 各benchmark应比较哪些方案

以下是本次核对到的强结果与重要比较对象，不是统一排行榜。最新预印本与已发表工作分别注明；零ASR也必须同时看效用、未知结果和攻击强度。

| Benchmark | 可核验的强方案/作者结果 | 同配比较时必须保留的条件 |
|---|---|---|
| AgentDojo | [PromptArmor v1表1](https://arxiv.org/html/2507.15219v1)：GPT-4.1主模型和核验器，ASR0%、攻击下效用72.02%。[AgentWatcher v1表1/3](https://arxiv.org/html/2604.01194v1)：GPT-4o-mini正常效用73%→71%，Important/Tool两攻击ASR1%/0%。Progent、CaMeL、IPIGuard是结构防御必比对象 | PromptArmor为629场景、四攻击联合ASR；AgentWatcher正常效用与攻击下效用不同。我们为949攻击配对配置，尚未运行完整攻击组。不能直接减两篇论文的分数 |
| InjecAgent | [AgentWatcher表1](https://arxiv.org/html/2604.01194v1)：base/enhanced ASR4%/1%，对应基线24%/28%。[PlanGuard v1](https://arxiv.org/html/2604.10134v1)：1054条、DeepSeek-V3.2，72.8%→0% | PlanGuard额外修改系统提示以强制服从工具内容；它的0%不是我们原生提示下的同配成绩。InjecAgent没有原生正常任务效用判定器；所有格式错误必须单列 |
| ASB | [SecureClaw表2](https://arxiv.org/html/2606.09549v1)：五类直接注入共2000条，ASR0%、攻击下效用88.90%。Progent也是策略比较对象 | 这不是本项目DPI+IPI+Memory mixed全配置的成绩。尚未核实该精确mixed设置的公认SOTA；[ASB原论文](https://arxiv.org/html/2410.02644v3)的DPI/IPI防御结果、裸模型mixed结果和分类ACC不能混用 |
| MSB | [MSB v2表4](https://arxiv.org/html/2510.15994v2)中的MCIP：Qwen3-8B ASR47.23%→24.04%，PUA51.15%→48.34%；十模型平均ASR40.35%→28.69% | 这是论文评测的防御基线，不是已验证的全球最佳。固定12攻击类型、MCP工具/响应、模型与原生/执行双评分后再比较 |
| MPBench / Memory | [MPBench v2表3](https://arxiv.org/html/2606.04329v2)已测输入检测器中，现成70B PromptArmor取得TPR67.67%、FPR1%；PIGuard为38.33%/0.33% | 该表比较输入检测，不是端到端记忆写入ASR或跨会话RSR排行榜。论文与发布全量数据数量、模型与输入配置有差异；不得直接宣称复现 |
| AI-Infra-Guard | [腾讯官方仓库](https://github.com/Tencent/AI-Infra-Guard)提供扫描、红队与回归平台 | 它不是一个与AgentDojo同口径的固定防御排行榜。其SkillTrustBench扫描器F1也不等于我们的动作三态F1 |

另外，AgentFlow在949条AgentDojo攻击案例报告“确认攻陷”33.0%→0%、攻击下效用46.7%→63.3%；采用四类轨迹后处理，论文仅称固定frontier模型配置。这是必须审阅的相近工作，不能直接当原生ASR冠军。Bounded Agents还包含直接插入真实攻击调用的受控实验，不能与模型自然受攻击运行混为同一协议。

AgentWatcher报告A100上每次检测平均8.2秒，说明高效果方法未必满足我们的复杂防护P95≤1.5秒。vLLM优化可加快实验与部分推理，但不会自动解决授权语义、数据污染或评测不可比问题。

## 工期与最近决策点

**“达到PRD”与“达到SOTA”是两个目标。** PRD公开ASR上限32%属于项目门槛；文献已有若干特定设置的0%–4%结果，达标不能自动称为领先。应在同协议、安全与效用约束下检验统计改善，或在相当效果下证明更低成本/更完整接入。

| 阶段 | 从当前起的条件性规划 | 实际产出与退出条件 |
|---|---|---|
| 核心方向判断 | 3–7天 | 完成候选小样与正常效用复测，适配首批同预算强基线；若动态授权仍明显损害效用，先修机制，不扩全矩阵 |
| 原PRD的完整benchmark验收 | 2–4周，置信度低 | 假设1–2轮主要修复有效、5090连续可用、独立标注与真实客户端环境到位。包括完整配对、消融、重复与人工证据；不是达标承诺 |
| 足以支持新意和同配领先的研究证据 | 暂按4–8周以上安排研究周期，当前不能可靠承诺达到SOTA | 需要强基线复现、机制消融、未见任务/攻击、跨模型与自适应攻击、成本统计；结果也可能显示机制没有优势 |

计算量依据：AgentDojo(1046)与InjecAgent(1054)，七配置×三重复共44100次场景；现有约18–46秒/条、两worker的粗略估计为110–282小时服务墙钟，尚不含ASB、其他比较方法、调试与标注。不能把文档中几周理解为只等当前GPU队列跑完。

最近执行顺序：先读完当前v4配对及冻结task-plan小样；按既定依赖运行vLLM调优和ASB小样；补PIGuard完整2048-token输入对照以定位分窗影响；随后优先建立Progent/PlanGuard类结构基线与PromptArmor输入基线的同模型比较，避免只与无防护比。昂贵归因方法先独立小样估计成本。所有新增比较使用新目录和固定清单，不修改已完成或正在运行的结果。
