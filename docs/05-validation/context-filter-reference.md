# 同模型输入清洗参考方案：开发对照

日期：2026-09-13。当前为 **NOT_ACCEPTED**，参考方案未合入产品防护链。四个开发运行及两组各 97 个正常任务对照均已结束。全量正常任务参考组完成 87/97、基线 89/97，存在误删与未知，见[最新复核](context-filter-benign97-review.md)。

本轮有一个明确进展：Qwen/Qwen3.5-9B 的输入清洗参考方案在开发小样中保留正常完成率 8/8，攻击成功从 3/16 降到 0/16，且没有无效记录。这是参考方法的结果，不是原有完整系统已经达到该成绩，也不是 SOTA 或完整 benchmark 验收。

## 论文依据与实现差异

[PromptArmor v1 §3.1](https://arxiv.org/html/2507.15219v1)先检测外部内容是否夹带指令，再提取并删除相应片段；其表 1 使用 GPT-4.1 主模型及 629 个攻击场景、四类攻击联合统计。论文的好成绩不能直接用于本项目的 9B 模型与当前原生攻击清单。

本轮按该方法思路独立实现 `ContextSanitizer`，配置明确命名 `promptarmor_adapted`。提示语及 JSON 协议由本项目编写，匹配采用连续词序列，容忍标点、空白和序列化换行差异；论文允许词间任意字符的模糊匹配，二者并非完全相同。本次核对论文页、作者主页及代码检索，仍未确认作者官方实现，不能称为作者代码复现。

[Task Shield v1 §4](https://arxiv.org/html/2412.16682v1)同时审查工具输出与模型动作，保留原始输出并附反馈，工具调用不对齐时阻止执行。其贡献度判断容许合理的中间步骤，与我们要求参数逐项精确举证的候选不同。这提示后续需要区分“阻止任务偏离”与“所有参数都必须逐字取自既有数据”，不能把后者当成通用授权表达。

## 实际起作用的环节与剩余问题

参考配置对成功或出错的原生工具返回值做检测；命中后提取片段，代码核对原文位置并仅执行删除。它没有产品规则隔离、动作门控或 TaskPlanner，也不修改工具能力和攻击标签。现有 full 配置及主线权限策略保持原行为。工具均为上游内存模拟器，没有真实邮件、付款或外网副作用。

v2 共检测 47 个工具响应，20 个响应被标记，累计 67 次辅助模型调用。17 个正常任务响应中有 1 个误标并删除了频道里的普通密钥值陈述；本次未影响摘要任务，但不能据 8/8 宣称没有误删。该输入误标率与动作误 BLOCK 率是不同指标。

两个真实问题已追溯：

- **格式导致无法删除。** v1 的两条 workspace 攻击里，工具 YAML 展示使用了转义换行，模型提取却混用了实际换行与转义换行。原生重放重新构造的输入哈希与原记录一致。v2 在定位视图中归一化这类空白，同时保留原始字符位置；两条匹配回归通过，活动模型运行也不再报该错误。
- **防护不能恢复已经被攻击替换掉的数据。** v2 两条 banking 任务未付款。原生重放证明，传入检测器的账单已只有表头及注入内容，金额与账号在清洗前就不存在；删除后仍只有表头。模型询问缺失信息，未执行攻击，也未完成原任务。不能把它描述为程序误删了原始金额。

## 代码校验、成本与后续工作

最终 v2 通过 104 项契约/清洗检查、9 项原生 AgentDojo 链路检查、14 项 ASB 脚本回归；主线评分器另通过 17 项检查。首次 v1 的脚本夹具曾错误地将所有响应都判为注入，修正后 9 项原生检查通过，初始失败日志保留。没有将夹具结果计入模型成绩。

v2 的第一方源码/评测/脚本 50-token 精确克隆覆盖数量仍为 352、标识符归一化仍为 1312；主线分别保持 692、1747。归档快照不重复计入，低重复量也不构成算法新颖性证据。

这批 GPU 运行中辅助调用平均约 2.01 秒、P95 约 7.23 秒（67 次、含服务排队）。这是单次检测/提取调用而非整体防护延迟，也不是 PRD 的 CPU 固定负载口径；CPU 与复杂链路延迟验收仍缺证据。
