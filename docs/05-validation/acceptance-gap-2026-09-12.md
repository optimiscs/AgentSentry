## 瓶颈定位

1. 语义授权是首要效果瓶颈。28个基线成功的任务在防护组丢失，另有3个新增成功，净损失25个；丢失的28个中25个出现ASK、1个出现BLOCK。全组31/97任务出现ASK，调用级原因共141次目标需要审批、44次副作用升级。频次包含重试，不当作独立案例数。字面目标匹配和粗粒度副作用合同不能充分表达“查出联系人后发消息”“由发票确定付款对象/金额”。
2. 拒绝后恢复不足。7条防护轨迹耗尽15步预算；延长时间本身不能使未获授权动作合法。不能靠自动批准ASK改善效用。
3. 模型原生协议仍不完全稳定。20:10快照中InjecAgent基线记录304/1054，290有效、14无效/错误；只说明前段有效率95.39%，不能作为完整攻击结果。27B基础能力明显优于此前7B，但结构化输出、长任务和参数适配仍需验证。
4. 新语义验证的成本未知。隔离候选task-plan-v1只以原始用户任务及审查过的工具目录规划，动态参数依赖实际允许执行的工具结果，完整参数哈希绑定后仍经过硬策略。238项pytest和6项脚本模型/原生模拟工具链路测试通过；未做真实模型效果或时延验证，未合并到活动服务。模型对任务语义的判断仍是信任假设，不是形式化证明。新增LLM调用可能与复杂路径1.5秒目标冲突。
5. 验收证据不完整。规则基线、四项消融、三次重复、ASB实际混合攻击、MSB/Memory/AI-Infra-Guard、独立标注、真实Codex/Claude Code E2E和独立安全评审仍有缺口。实际厂商客户端受现有认证/安装及宿主沙箱能力限制；事件夹具成功不能代替真实CLI验收。

单卡5090已能承载现有27B NVFP4 / 32K / 两worker配置。现阶段没有显存不足导致该批处理无法运行的证据；GPU吞吐限制实验周转，多卡不能直接修复授权逻辑或补齐人工标注。

## 时间估算与假设

以下是规划区间，不是达标承诺。按2026-09-12 20:10快照：当前InjecAgent基线每条平均17.86秒，两worker；尚余750条基线和1054条防护。若防护速度相近，纯计算约4.5小时，留出波动按**4–6小时**估计。完整防护尚未开始，可能比该估算慢。此估算只覆盖现有队列，不覆盖新候选或全部验收。

- **下一轮核心效果判断：3–7天的规划区间。** 包括候选真实模型小样、正常效用配对、AgentDojo攻击与InjecAgent核心配对及必要修复。24小时内可争取获得候选可行性反馈；没有模型实测前，不承诺这一阶段一定把效用从59提高到80。
- **按文档完成全量benchmark验收：暂按2–4周规划，置信度低。** 前提是1–2轮主要算法改动奏效、单卡稳定连续运行、独立标注人员与真实客户端环境及时到位；复杂时延不达标或语义误判多时还需延长。
- **正式发布另外包含七天稳定性观察和独立安全签收。** 可与部分评测并行，但不能压缩成几个小时的跑分。

量级依据：仅AgentDojo 1046条（97正常+949攻击）和InjecAgent1054条，每配置共2100条；三种系统配置加四种消融、每种三次，共44100次场景运行。以当前每条约18–46秒、两worker粗估，约110–282 GPU服务墙钟小时，即约4.6–11.7天连续运行，尚未包含ASB、候选附加模型调用、调试重跑与人工复核。并非全部都是当前代码已支持或已经排队的作业。

下一决策点是候选真实模型的效用/有效率和时延实测。先证明核心方案有可能同时满足安全、效用、时延，再冻结全配置大矩阵；任何失败保留原始记录，不降低门槛或选择性删样本。
