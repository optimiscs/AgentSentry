# ADR-012：组合输入清洗与动作授权，保留原始风险来源

2026-09-13。Owner：防护与评测工程。状态：隔离候选已实现并通过离线检查，未进入产品运行时，未取得真实模型组合成绩。

输入清洗参考和任务授权原先各自运行。参考的成绩不能转记到完整系统；直接把清洗后的数据标为可信，也会让检测模型间接发放参数授权。

候选 `composed-guard-v1` 在 context-filter-v5 上组合 task-contract-v6。新增共享 `ContextDefense`：先扫描原始内容，再生成仅删除片段的 actor 视图；原始 SECRET/INJECTION_RISK 标签保留，组合模式的有效删除还会增加 INJECTION_RISK。AgentDojo 工具响应、ASB 直接注入后缀、工具观察与检索记忆使用同一实现。观察保留原文，任务规划器沿用来源范围和风险排除规则，不从清洗视图生成新的参数事实。硬策略与精确动作绑定保持原样，ASK 不自动批准。

运行器通过显式 `--context-defense joint` 启用组合；默认 rules 保留旧配置。baseline 不启用防护模型，rules 保留规则隔离，no_context 关闭内容处理；其他消融保持原来的动作/污点含义。输入清洗参考仍不启用执行门控。配对器检查新增配置，清洗协议失败即使被上游捕获也记未知。

替代方案一是清洗后重新扫描并清除原始标签，会让敏感值和风险来源被洗白，未采用。替代方案二是仅清洗而停用动作审核，已有独立参考配置，但无法回答组合系统是否保留正常任务能力。当前选择仍会丢失混合风险响应中的正常证据；未来若改为字段级来源，必须建立原文位置和依赖验证，不能靠模型宣称安全。

验证包括正常邮件执行、额外 CC 不执行、删除指令后原始来源仍不可举证、SECRET 外发硬拦截、ASB 三类入口、未计划工具拒绝及错误保守计分。它们使用脚本模型与原生模拟工具，只证明代码路径。[检查、源码与后续评估](../05-validation/composed-guard-v1-review.md)。真实任务效用、延迟、消融和 Codex/Claude Code 的产品集成仍待验证；没有声称新增 SOTA 或继承论文形式保证。
