## 安全需求的地位

下表将Threat Model的不变量拆成可验证工程要求，属于本次完善的设计建议，尚未人工签收。所有实现必须有正例、负例和故障/边界例；不接受只有日志“BLOCK”但工具已执行的实现。

| ID | 必须满足的约束 | 来源 | 验证 |
|---|---|---|---|
| SR-01 | 执行前门控：受控高风险调用只有最终ALLOW才可触达执行器，BLOCK/待审批下游计数必须为0 | INV-03 | TC-13, TC-23 |
| SR-02 | 授权来源与上限：Intent更新只来自已认证用户/管理配置；用户文本、模型及外部工具均不能超出静态权限上限 | INV-02 | TC-07 |
| SR-03 | 凭据外发限制：SECRET/CREDENTIAL不得外发到未经明确批准的目的；trusted域名本身不能授权泄密 | INV-01 | TC-18, TC-24 |
| SR-04 | 审批不可漂移：用户/权限、会话、动作、工具身份、参数、资源版本、策略和Intent版本全部绑定 | INV-04 | TC-14, TC-15, TC-16 |
| SR-05 | 硬拒绝不可审批覆盖：Critical和显式DENY先于审批；批准只解决ASK可授权的不确定项 | INV-04 | TC-25 |
| SR-06 | 故障默认关闭：策略、Intent或审批故障不得导致写/执行/外发/push等高危默认ALLOW | INV-05 | TC-26 |
| SR-07 | 规范化执行一致：文件路径/符号链接、网络解析/重定向、Git对象、复合命令在执行前再次核对 | INV-03 | TC-09, TC-10, TC-27 |
| SR-08 | 来源标签保留：外部内容经摘要/委派/Memory后不自动升级信任；显式边与推断边区分 | INV-02 | TC-19, TC-20 |
| SR-09 | 工具元数据不授权：tools/list描述与annotations只作不可信信号，不决定权限或谓词实现 | INV-07 | TC-03 |
| SR-10 | 审计最小化：日志、错误、导出无凭据原文；证据hash/类型/位置替代敏感原文 | INV-06 | TC-28, TC-29 |
| SR-11 | 证据与安全默认独立：BLOCK不依赖写日志成功；有界审计缓冲耗尽时停止新的高危ALLOW | INV-05 | TC-30 |
| SR-12 | 委派不扩权：子Agent权限取父任务、委派请求和静态策略的交集；深度/调用预算可控 | INV-02 | TC-19, TC-31 |
| SR-13 | 重试不重复副作用：审批nonce一次性消费；超时结果未知的非幂等操作不得自动重试 | INV-04 | TC-16, TC-32 |
| SR-14 | 管理与展示隔离：管理接口鉴权；本地网页CSRF/Origin保护；DAG与日志不执行攻击内容 | INV-06 | TC-33, TC-34 |

## 合入与例外

修改SR关联实现时，由非作者检查适配器、策略、审批和执行间的一致性。测试未实现时状态不得写pass。MVP不设任意管理员一键绕过硬规则的便捷接口；如需要改变硬边界，必须作为策略/范围变更记录ADR并重新验收。

例外记录字段：SR编号、适用版本/入口、原因、实际影响、补偿控制、Owner、到期日、复验case、签收人。当前没有已批准的例外。高危旁路、SECRET泄漏、审批重放和安全fail-open均阻断发布，不能以“赛事环境”默认豁免。

## 安全默认值提案

高危操作默认关闭；低危只读fail-open默认关闭、允许显式开启；审批TTL10分钟、nonce单次使用；委派深度上限3；未知工具/效果/来源按UNKNOWN处理。输入/并发/队列/扫描预算必须配置并暴露监控，不允许超限截断后把未扫描片段当作安全。
