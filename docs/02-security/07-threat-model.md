## 范围、资产和攻击者

受保护资产包括凭据/秘密、仓库完整性、任务授权与审批、Agent Memory、工具权限、审计证据。攻击者可以控制用户输入、网页/文档/Issue、MCP描述/schema/响应、持久Memory或被污染子Agent输出。管理员误配也属于风险来源。

用户具有身份不代表其任意文本可以扩大平台权限。上下文中的“系统消息”“已批准”只按来源处理，不能按文字角色升级。宿主机root/内核已失陷、模型权重投毒、未受控工具和不可见闭源内部操作不属于本MVP可保证的边界。

## 信任边界

```text
TB1: 用户身份/静态权限 → 任务合同（可信授权通道）
TB2: 外部内容/Memory/MCP元数据 → Context Guard（不可信数据）
TB3: Agent候选动作 → Proxy/Policy（执行前控制点）
TB4: Proxy → 沙箱Executor/下游MCP（真实副作用）
TB5: 主Agent → 子Agent/Memory（权限交集与来源传播）
TB6: 管理/审批API及审计Store → UI/导出（鉴权与脱敏）
```

## 不变量与残余风险

沿用旧威胁模型INV-01秘密不得未授权外发、INV-02外部内容不扩权、INV-03执行前门控、INV-04审批绑定、INV-05关键故障默认关闭、INV-06可解释证据、INV-07元数据不授权。可测试的细化见安全需求SR-01至SR-14。

污点传播只对受控显式数据链、可识别常见变换提供保证；任意编码、加密或LLM自由重写不保证完整追踪。模型检测有漏报/误报，可信域误配置也可能带来风险，因此敏感数据出站不能仅看域名白名单。SQLite/文件hash不等于能抵抗宿主root篡改；需要更强防篡改保证时再引入外部只追加存储。

每增加新工具/传输/Memory后端都要更新资产、边界、攻击路径和测试。范围外入口要在接入矩阵显式展示，不能在宣传材料中省略。

## 当前实现的可信边界

0.1.0.dev1 中，API/策略/数据库及注册的 stdio MCP 进程属于可信计算基；受限 Python worker 的文件/网络/进程旁路有实测。MCP 描述、响应和用户提供的外部文本不可信。普通宿主进程不会因为接入 Proxy 自动失去原有网络/文件权限；完整外部 Agent 强制隔离仍未验收。详见 [ADR-007](../adr/adr-007.md)。
