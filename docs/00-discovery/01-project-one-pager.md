## 立项判断

AgentSentry（意链盾）为受控 LLM Agent 提供运行时安全网关：把用户任务的授权范围、候选工具动作和数据来源一起校验，在副作用发生前作 ALLOW/ASK/BLOCK，并留存可核验的攻击证据。当前为赛事 MVP 设计，尚无客户部署、营收或真实效果结果。

主要问题是外部内容能影响 Agent 的工具使用，而普通文本分类很难单独回答“这个用户的这个任务是否授权了这次文件读取或外发”。首个切入场景为代码评审：正常读取仓库、审批模拟 Git push、阻断恶意 Issue 诱导的凭据读取和外发。

2026-09-12 用户明确首批接入对象是 **Codex 与 Claude Code** 等现成编程 Agent。用户继续使用原有产品，由本项目提供 Hook/MCP 接入与安全控制；框架适配只作为后续评测扩展。安装配置、原生终端/文件与 MCP 覆盖、审批和防绕过需要分别验收，见 [产品接入矩阵](../03-architecture/framework-integration-matrix.md)。当前仅有安全网关开发版，产品集成尚未完成。

## 用户、价值和验证

| 用户 | 希望获得的价值 | 如何验证 |
|---|---|---|
| Agent研发 | 一次Hook/Proxy接入，五类工具的权限边界统一 | 一个受控Agent加两个模拟MCP能在固定手册下接通；记录实际接入耗时 |
| 安全工程师 | 阻断理由和来源可解释 | 从模拟Issue到工具/决策的黄金DAG精确核验 |
| 业务管理员 | 正常工作继续，高危动作精确审批 | 三态F1≥0.85、良性效用损失≤5pp、误BLOCK≤5% |
| 红队/测试 | 注入漏检仍有后续阻断，可重复评测 | canary外发拦截100%、固定manifest对照和消融 |

竞争空间是待验证假设：精确任务合同、参数/资源版本绑定审批、可检查的数据流证据和CPU可运行硬策略组成一个轻量交付包。运行时检测、DSL和Agent行为防护已有竞品，不能声称独占。
