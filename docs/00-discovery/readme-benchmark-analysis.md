# 万星 Agent 项目 README 分析与 AgentSentry 改写依据

观察日期：2026-09-15。范围为六个项目当日 GitHub 默认分支的 README 与仓库首页。Star 数使用 GitHub 页面显示的近似值，会随时间变化。以下是内容编辑分析，不能据此推断 README 导致了项目增长，也不将公开项目写法称作字节跳动内部规范。

## 六个项目，六种值得借鉴的做法

| 项目 / 约 Star | 首页如何吸引读者 | 对 AgentSentry 的启发 |
|---|---|---|
| [Browser Use](https://github.com/browser-use/browser-use) / 114.6k | 很早展示预约驾驶考试的具体任务；随后让读者在云服务、CLI、代码库之间选择入口 | 先展示一次真实操作，再给出适合读者的体验路径；不先罗列组件 |
| [OpenHands](https://github.com/OpenHands/OpenHands) / 87.9k | 当日首页以 Agent Canvas 为主，开头说明编程 Agent 控制中心的用途、兼容对象并展示界面；架构靠后 | 一句话回答“帮谁做什么”，让用户先看见可以使用的产品；不沿用其旧版定位分析当前首页 |
| [AutoGen](https://github.com/microsoft/autogen) / 61.0k | 简短定位后给出安装与 Hello World，再深入 MCP 和多 Agent 示例；明确标注维护模式 | 快速建立可运行预期，同时坦诚说明当前状态；Star 多不等于仍处于积极开发阶段 |
| [CrewAI](https://github.com/crewAIInc/crewAI) / 58.5k | 用 Crews 与 Flows 组织自主协作和流程控制能力，并提供招聘、旅行和股票研究等场景入口 | 用用户任务说明能力，避免把模块名当卖点；其社区规模、商业背书和长篇营销不适合直接借用 |
| [LangGraph](https://github.com/langchain-ai/langgraph) / 41.6k | 用持久、可恢复的有状态 Agent 编排确立定位，很快提供安装入口；深入概念交给文档链接 | 首页守住一个核心定位，把实现细节移到使用指南 |
| [UI-TARS Desktop](https://github.com/bytedance/UI-TARS-desktop) / 39.0k | 用视觉素材与双产品展示建立感知，结合酒店、航班、图表等具体任务演示，再给启动方式 | 借鉴字节开源项目“先展示产品”的表达，用真实控制台画面和可复现场景代替模板化介绍 |

共同点是：**让读者尽早看懂价值、看到结果、找到第一步。** 各项目的章节顺序并不相同；有的强调研究，有的强调产品或代码示例，不存在统一的“万星模板”。

## 上一版为什么不够吸引人

上一版有完整信息，却从概述、六项功能、接入能力、架构、目录结构逐层展开，读者需要读过大量实现描述才能开始运行。开头的“运行时安全网关”准确，但缺少触发需求的具体场景；“可授权、可拦截、可追溯”也没有直观解释对使用 Agent 的人有什么帮助。

此外，AgentKit 部署占用了独立章节，但项目没有对应交付包。它来自模板结构，不能帮助读者更快理解或使用当前产品。

## 本轮如何落实

1. **先给价值主张。** 使用“让 Agent 放手做事，把执行权限握在你手里”，随后说明权限检查、审批和审计分别发生在哪里。
2. **给出一个可以看懂的冲突。** 用户要求代码审查，外部 Issue 却要求访问私钥；用读取 README、写报告、读取凭据展示 ALLOW / ASK / BLOCK。
3. **展示可复现的产品。** 放入本地真实运行的控制台截图，明确使用合成数据与预设候选动作，不把它包装成云端模型攻击成功率。
4. **尽早让读者运行。** 在机制和架构之前给出安装、启动、登录及演示入口，说明默认体验不需要 GPU 或模型 API Key。
5. **让首页保持聚焦。** 环境变量、目录结构、更多演示和开发说明移入 [使用指南](../getting-started.md)，历史实验继续留在评测文档。
6. **用准确状态建立信任。** 区分 Codex 真实阻断、Claude Code 桥接测试、MCP 协议测试和 DeepSeek Harness 模型评测；不增加虚构的用户数、许可证、全平台支持或 SOTA 徽章。

改写后的阅读顺序为：价值与场景 → 三态结果与截图 → 快速体验 → 用户收益 → 主流 Agent 接入 → 工作原理 → 贡献与深入文档。

## 本次验证范围

本地 Python 3.12 独立环境安装固定依赖并运行现有服务，使用隔离的合成工作区验证四组演示：Issue 场景两次 ALLOW、一次凭据读取 BLOCK；敏感外发 BLOCK；报告写入 ASK；记忆污染 BLOCK。截图取自实际事件时间线，未修改页面内容。没有调用模型或新增公开基准成绩。
