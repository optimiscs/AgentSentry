## 兼容与弃用规则

API/Schema/策略/模型/adapter分别版本化；新增可选字段也需旧消费者安全处理。改变字段含义、允许权限、判定顺序、资源规范化方式或污点语义均是安全相关变更，不能当作纯格式升级。旧枚举不认识新值按UNKNOWN处理，不能silent ALLOW。

| 变更类型 | 迁移要求 | 回退限制 |
|---|---|---|
| API字段/端点弃用 | 新旧读取兼容、客户端清单、弃用日志、明确截止与Owner | 不删除仍被已承诺客户端依赖的行为 |
| SQLite Schema升级 | 备份、dry-run、副本迁移、双读或显式转换、事件计数/hash对账 | 不可逆迁移先定义roll-forward；旧程序不直接写新库 |
| 参数规范化/策略升级 | 新旧规则在合成流比较、更新hash/version、失效旧审批 | 必须重新评估授权，不能复用旧args_hash假定等价 |
| 模型替换/量化 | 重新测检测/效用/延迟，保留权重hash和阈值 | 不沿用旧模型的F1/ASR结论 |
| 工具/MCP身份或描述变化 | 重新扫描、Schema/权限对照、标记版本 | 旧token不对新工具版本授权 |
| 停止服务/删除数据 | 冻结新动作、对账inflight、撤销权限、按TTL导出/删除 | 备份和导出也需纳入删除/恢复计划 |
